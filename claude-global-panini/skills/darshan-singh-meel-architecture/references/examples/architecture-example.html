3 Problems

P1 · HIGH · Cost driver

Every mart rebuilt from all history each night

  • +materialized: table on all marts: each run rescans years of rows while only yesterday's orders change.
  • Costs: warehouse time grows with total history, not with daily volume
  • Evidence: dbt_project.yml:14, models/marts/fct_orders.sql:1
  • Fixed by: C1
P2 · HIGH · Single point of failure

One scheduler VM, no standby

  • Scheduler, worker and metadata DB share one VM.
  • Costs: VM down at 02:00 means no marts that day; recovery is manual
  • Evidence: infra/airflow/vm.tf:8
  • Fixed by: C2
P3 · MEDIUM · Scaling limit

Whole table loaded into memory

  • pd.read_sql with no date filter and no chunks.
  • Costs: out of memory once orders outgrows the VM's 8 GB
  • Evidence: extract/pull_orders.py:22-30
  • Fixed by: C3
P4 · MEDIUM · Tech debt

Revenue logic copied in 3 marts

  • Net revenue CASE copied; the review found the copies already differ on tax.
  • Costs: each rule change needs 3 edits; a missed one gives different totals per dashboard
  • Evidence: models/marts/fct_orders.sql:12-20, models/marts/fct_returns.sql:8-16, models/marts/fct_refunds.sql:8-16
  • Fixed by: C4
P5 · MEDIUM · Security

Infra applied by hand

  • terraform apply runs from personal laptops with admin keys.
  • Costs: no review or audit trail of infra changes
  • Evidence: README.md:20-24
  • Fixed by: C5

Changes

Each move: one pick and its alternatives; ask "use <alternative> instead" to rebuild the target around it.

C1 · fixes P1
  • Incremental marts: fct_orders, fct_returns, fct_refunds as incremental with unique_key and a 3-day lookback; warehouse down to Medium
  • Why: each run scans days of rows, not years
C2 · fixes P2
  • Scheduler on MWAA: run orders_daily on Amazon MWAA with 2 schedulers; retire the VM
  • Why: no single VM; patching and restarts move to the service
  • Pick: Amazon MWAA — DAG code moves unchanged; the AWS account already holds S3 raw
  • Alternatives: Snowflake Tasks — no scheduler to run; the Python extract needs a container · Dagster+ — asset lineage across extract and dbt; a new framework · Astronomer — managed Airflow on any cloud; a second vendor contract
  • Also needs: DAG imports checked against the MWAA Airflow version
  • Signal: infra/airflow/vm.tf:8
C3 · fixes P3
  • Watermarked, chunked extract: pull_orders reads rows with updated_at after the last watermark, 50k rows per chunk
  • Why: memory and run time follow daily volume
C4 · fixes P4
  • One shared revenue model: int_order_revenue holds the CASE; the 3 marts ref() it
  • Why: one edit per rule change; totals cannot drift
C5 · fixes P5
  • Terraform from CI: plan on pull request, apply on merge with a deploy role
  • Why: every infra change reviewed and logged
  • Pick: GitHub Actions — the code is on GitHub; plan and apply sit next to the review
  • Alternatives: HCP Terraform — runs, state and policy managed; a paid tier for teams · Atlantis — plan and apply from PR comments; a server to host
  • Signal: README.md:20-24

Options considered

Evolve in place · chosen
  • C1–C5 on the current stack
  • Gains: lowest risk; each step ships and rolls back alone
  • Costs: managed Airflow adds a fixed monthly fee
  • Size: same 3 models, 1 DAG; +1 shared model, +2 workflow files (estimate)
Move transforms to Spark
  • rewrite the marts as Spark jobs
  • Gains: one engine for extract and transform
  • Costs: rewrite of every model, a second platform to run, no saving at this volume
  • Size: 3 models (~70 lines) → ~3 Spark jobs (~200 lines, estimate); tests rewritten
Run weekly
  • cut the schedule to weekly
  • Gains: about 85% fewer runs, no code change
  • Costs: dashboards up to 7 days old
  • Size: no code change

8 Open questions and assumptions

Questions

  • Do dashboard users need data before 06:00? If not, C1's speed gain matters less than its cost gain.
  • Is an MWAA fee approved? If not, C2 becomes a standby VM with a shared metadata DB.

Assumptions

  • Daily new or changed rows stay under 1% of orders — C1 and C3 savings scale with that share
  • Late updates arrive within 3 days — older edits would miss the incremental lookback
