models/marts/fct_order_revenue.sql 1 Must

New mart: one row per order with total revenue, read by dashboard, report and export

MUST · Data · lines 12-18
  • Problem: order_total is summed after joining order_items, so an order with 3 items counts 3 times.
  • Why: Revenue on the dashboard and monthly report is overstated for every multi-item order.
  • Fix: Sum order_items.amount (item grain) or join after aggregating items to order grain.
select o.order_id, sum(i.amount) as revenue
from {{ ref('stg_orders') }} o
join {{ ref('stg_order_items') }} i using (order_id)
group by o.order_id

src/export/orders_api.py 1 Must · 1 Should

New endpoint GET /orders/export: filters the mart by date and streams CSV

MUST · Security · lines 31-34
  • Problem: The from_date request value is put into the SQL string with an f-string.
  • Why: Any caller can run arbitrary SQL against the warehouse (SQL injection).
  • Fix: Pass it as a bound parameter.
  • Evidence: probe: from_date=2026-01-01' or 1=1-- returned every row synthetic
cur.execute("select * from fct_order_revenue where order_date >= %s", (from_date,))
SHOULD · Performance · lines 36
  • Problem: A request without to_date exports every order since from_date in one response.
  • Why: A wide range loads millions of rows into one request and times out.
  • Fix: Require to_date and reject ranges over 31 days with a 400.
