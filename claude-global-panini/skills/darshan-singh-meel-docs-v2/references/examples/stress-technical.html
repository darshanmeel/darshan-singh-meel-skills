Customer orders warehouse (stress example)

layout stress test: long identifiers, 12-way fan-out, 12 tables in two ERs, 4-stage journey, long card values · all names and values illustrative

  • Loads partner order files for 12 regions into very_long_schema_name.stg_customer_orders_incremental_v2 every night
  • Merges the 12 region partitions into one staging table
  • Builds analytics_mart_schema.fct_customer_order_lines_enriched_daily_snapshot for finance
  • Alerts #data-oncall-alerts when a region task fails
  • Doesn't produce the partner files — the partner SFTP export does
  • Doesn't calculate tax — the finance system does
  • Doesn't manage warehouse roles — platform team
  • Nightly at 04:00 UTC, not real-time
  • One slow region delays the merge for all 12
  • Late corrections older than 7 days are not picked up
  1. Region tasks retry on any error, including bad files Confirmed (review)
  2. order_line_shipments can double-count split shipments Not verified
  3. Currency rates are read without a date filter Confirmed (test)
