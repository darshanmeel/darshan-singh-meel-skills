2 Context

Four sources land in Snowflake once a day; dbt models build the vehicle view; three consumer groups read it.

Key: grey = source · white = step · teal = Snowflake table · purple = consumer · GIVEN = already in place · dashed = phase 2

Snowflake and Airflow in this flow

  • Snowflake holds raw, core and marts; retention is a table property, so the seven-year cost history (FLT-7) lives in core tables, not in Time Travel.
  • Airflow runs one DAG at 05:00: three extracts, COPY INTO raw, dbt build, dbt test, dashboard refresh by 07:00 (FLT-2).
  • The fuel statement has no connector; finance uploads it to a Snowflake stage once a month until the provider offers SFTP or an API.

5 Identity and linking

The vehicle is the one entity everything hangs on; VIN is the master key, plate and fuel card are mapped to it with validity dates.

Key: boxes = entities with their identifiers · lines = join key; plate and card_no go through effective-dated mapping tables

VIN as master key; plate and card mapped by date

  • Master key is vin; vehicle_id is kept as the FMS surrogate.
  • Plate → VIN: a mapping table with valid_from/valid_to, built from the daily FMS snapshots, so a work order joins the vehicle that carried the plate on opened_at.
  • Card → VIN: same pattern on card_no; FMS holds today's assignment only, so re-assigned cards before the first snapshot cannot be attributed. Owner to decide: accept, or ask FMS for history.
  • Telematics VINs unknown to FMS are loaded and reported, not dropped (section 8: 3 of 20 VINs).

VIN overlap, empty cards, empty odometers

  • 17 of 20 FMS VINs appear in telematics; 3 telematics VINs are unknown to FMS: likely decommissioned or wrongly keyed vehicles. We load and report them (section 5).
  • card_no is empty for 25% of vehicles: fuel cost cannot be attributed for a quarter of the fleet until FMS is completed.
  • odometer_km is empty in 5% of readings: the FLT-12 rule compares against the last non-empty reading.
  • fault_code is set in 22% of readings; severity is always set with it.
  • plate is unique in the sample, which supports the plate mapping; its stability over time is not visible in three days.

11 Gaps, assumptions and risks

Gaps

  • Service interval per model: no source (FLT-3, W1).
  • Planner → depot mapping: no source (FLT-8, W4).
  • Volumes: row counts per source and growth are not stated; sizing of warehouse and stage is pending.
  • Fuel card assignment history: FMS holds the current card only.

Assumptions

AssumptionWhy it matters
The FMS API returns all vehicles of a depot in one pagePaging changes the extract task (W6)
Plates are unique at any point in timeThe plate mapping joins work orders to vehicles
Finance accepts a monthly fuel figure in a daily dashboardOtherwise FLT-2 needs a daily fuel feed, which does not exist
Read-only JDBC access to the workshop database is grantedNo access → file export from the workshop team instead

Risks

  • Manual fuel upload is skipped in a month: cost per vehicle is understated. Mitigation: a freshness test on raw.fuel_txn alerts finance.
  • Plate re-registration between two snapshots goes unseen: a work order joins the wrong vehicle. Mitigation: unknown-plate report after each run.
  • Telematics VINs unknown to FMS grow over time: fleet counts drift between dashboard and FMS. Mitigation: the unknown-VIN report is reviewed weekly by the fleet manager.

12 Glossary

VIN — Vehicle identification number, 17 characters, unique per vehicle for life
FMS — Fleet management system: master data, assignments, status
Telematics — On-board unit data: odometer, engine hours, fault codes
Work order — One workshop job, planned or unplanned, with labour and parts cost
Service interval — Kilometres between two planned services, per model
Snapshot — A daily copy of a source table, used to rebuild history
Mapping table — Key → VIN with validity dates (plate, fuel card)
Row access policy — Snowflake rule that filters rows per user role
Snowpipe — Snowflake load on file arrival in a stage
DQ — Data quality: tests that reject or report bad rows
