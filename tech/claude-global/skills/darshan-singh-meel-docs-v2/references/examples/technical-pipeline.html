Orders pipeline

Spark on a job scheduler · daily · order events → sales views

  • Reads order events from the landing table once a day
  • Keeps the newest version of each order (order_id + status)
  • Splits orders into lines, discounts and shipments
  • Publishes 4 read-only views in export.sales
  • E-mails the team when a task fails
  • Doesn't receive events — a separate feed fills landing.order_events
  • Doesn't calculate totals — views copy tables one to one
  • Doesn't grant read access — platform team
  • Daily at 05:00, not real-time
  • Each task stops after 1 hour
  • No automatic retry
  1. Two shipments with the same shipment_no — one is lost Confirmed (code)
  2. Removed lines may stay in the views Not verified
  3. Library version differs between tests and production Confirmed (code)
