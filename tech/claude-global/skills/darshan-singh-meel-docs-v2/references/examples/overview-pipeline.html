overview

Orders pipeline

Spark on a job scheduler · daily · order events → sales views

  • Gives analysts one current, flat copy of every order
  • Updates once a day, before 06:00
  • Splits each order into lines, discounts and shipments
  • Doesn't take orders — the order system does
  • Doesn't build reports — analysts do
  • Doesn't manage who can read the data
  • Data is up to one day old
  • A failed run is not retried automatically
  1. Some shipments can go missing when two share a number Confirmed (code)
  2. Removed order lines may still be counted Not verified

1 What it is and why

  • What: Collects every order update from the order system and keeps only the latest version of each order.
  • Why: So nobody has to read raw order messages to answer a question about an order.
  • Key idea: The newest update of an order replaces the older one; older updates that arrive late are ignored.
  • Result: Simple tables analysts can read directly, ready every morning.

5 Value and cost

  • Value: One trusted, current copy instead of many raw messages.
  • Cost: One small daily compute job; no always-on servers.

6 Schedule

  • Production · Runs Every day at 05:00 · Notes Data ready by about 06:00

7 Design and operational risks

  • Up to one day behind the order system.
  • One failed step holds back the whole morning update.

8 Words used

  • Order — one purchase, with one or more lines
  • Line — one product in an order
  • Latest version — the most recent update of an order
